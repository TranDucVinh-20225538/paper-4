## Q1. When AUROC is flat, why? (Check 1)

**Registered predicate** (`reach.check1_reading`, unchanged). Order of tests on (|dAUROC|, S(δ_med), F) at τ=0.002, S_high=0.02, F0=0.0001: (1) inconsistent if |dAUROC| > F beyond sampling error; (2) moved if |dAUROC| ≥ τ; else flat, and then (3) cancelling if F > F0; (4) **invariant** if S ≥ S_high; (5) else **insensitive**. Invariant therefore requires flat AUROC *and* high reach at the observed δ_med *and* almost no realised reordering. It is not a test that δ = 0.

**Why knn10 receives invariant and maha does not (ortho_scale).** Q4 already shows knn10 median |dAUROC| = 0 and maha at 3.0e-06 under ortho_scale — both flat at τ. The label still splits them because invariant demands S(δ_med) ≥ S_high, not δ = 0:

knn10's scores move under scale (median δ_med large) so many ID–OOD pairs sit inside 2δ and S ≈ 1, while ranks — hence AUROC — stay flat: registered invariant. The *ridged* Mahalanobis the audit scores with (eps = 1e-5) is rank-invariant under the affine group to within the Theorem 2 deviation — not the exact Theorem 1 statement, which is about the unregularised refit and is only computable on backbones where λ_min(C) sits well above ε²_float32 (see maha_noridge below). Its scores also move (median δ_med = 2.54 on this slice); under the ridge the ranking is preserved to within that deviation, and separately the ID–OOD margins are wide relative to the displacement, so S stays ≪ S_high. Both are true; neither is "the scorer did not need to move." The registered invariant label is **structurally unreachable** for a scorer whose margins dwarf δ, because S(δ) is a worst-case bound over *arbitrary* perturbations of size δ and carries no information about a ridge-near-monotone one. That is a miscalibration of the label by construction, not a failure of maha.

### Rank-preserving reading (what the paper uses)

Rank-invariance is a statement about ordering, so test ordering. Over each evaluation population (ID test + OOD rung):

    rho = spearman(s(z), s_tilde(T z))

Flat cases then separate on their own evidence (`reach.check1_rank_reading`, rho_tol=1e-03): **invariant** if rho = 1 within tolerance (report 1−rho and the count of discordant pairs among a PAIR_SEED sample); **cancelling** if rho < 1, AUROC flat, F > F0; **insensitive** if rho < 1, AUROC flat, S < S_high; **flat_high_reach** if rho < 1, F ≤ F0, S ≥ S_high (the registered-invariant case without rank preservation). The registered predicate is not edited — that it is unreachable for a wide-margin flat scorer is a finding about Check 1, which ships as a library. `n_discordant_pairs` counts sampled pairs that were untied before and whose sign(s_i−s_j) changed after — including before-untied → after-tied, not only flips.

On dinov2 and vitb16, λ_min(C)/λ̄ sits at 3.1e-14–1.3e-13 (against ε²_float32 = 1.4e-14); the variance in that direction is float32 rounding noise, the unregularised covariance is not a computable object, and eps = 1e-12 implements a differently-ridged solve conditioned ~10⁷ worse — noridge is 27–28× *worse* than ridged under ortho_linear, and the same reversal holds on ortho_scale, general_affine, and zca. The exact-invariance result that motivates the scorer choice cannot be realised on DINOv2 or ViT-B/16 embeddings at the precision those embeddings carry. The ridged statement is therefore not a concession: it is the only well-posed claim available on two of five backbones.

### Prediction: kde vs kde_det under ortho_linear

Written before the kde/kde_det rank columns are read. kde uses Scott's rule with σ̄_c, the arithmetic mean of per-dimension standard deviations — rotation-dependent (AM of square roots is concave). kde_det uses det(Σ_c)^{1/(2d)}, a geometric mean — rotation-invariant. Under ortho_linear (pure rotation about the origin):

- **kde** should give ρ < 1 with a discordant count well above cosine/knn10's 0–1.
- **kde_det** should give ρ = 1 to float tolerance where kde does not.

If that separation does not appear, the bandwidth mechanism is not what Q4's kde_det ortho_scale 1.0e-08 vs kde 3.0e-04 was reading, and that needs saying.
