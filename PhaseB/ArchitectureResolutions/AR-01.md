# Architecture Resolution AR-01

**This is neither an Execution Amendment nor a Protocol Deviation — a third, distinct category.**
Per Vinh (2026-08-05): the protocol (`22_Experimental_Design.md` §3) locks the *mechanism*
("representation intervention → geometry → accessibility → reliability"), not any specific
*implementation* — it says "mirror [GRL + orthogonality] as closely as an adapter allows," which
does not require reproducing CSG-Lite's dual-encoder design. Changing implementation to fit a frozen
FM is therefore not a Protocol Deviation (the hypothesis — representation intervention → geometry →
accessibility → reliability — is untouched). It is also not an Execution Amendment (EA handles a
missing artifact, split, embedding, or classifier head — a known "what," missing "how much/where."
Here, the intervention architecture itself — the "what" — has never been defined). This is a
**scientific design question**, resolved through evidence (existing literature), not through
extraction or computation.

## The question

**Revised 2026-08-05, per Vinh — the original framing risked starting from CSG-Lite and searching
for a replacement, which is exactly backwards.** AR-01 must start from the literature, not from
CSG-Lite. Corrected question:

*What intervention architectures already exist for modifying frozen vision foundation model
representations, and which design principles are preserved across them?*

CSG-Lite does not appear anywhere in the Architecture Study (§ below) — it is not the search target,
not a comparison point, not mentioned. It only re-enters at Step 2, once the literature's own map is
in hand.

Traced from `Stage4_Intervention_Architecture_Gap.md`'s three confirmed gaps (all agreed by Vinh):

1. **Context embedding** — CSG-Lite's orthogonality term needs a second, independently-encoded
   embedding from a separate context-crop CNN branch. No equivalent exists for a single frozen ViT.
2. **Adapter placement** — dimensionality, injection point, and mechanism (LoRA / bottleneck
   adapter / residual adapter / prompt tuning / feature projector / other) are all undecided —
   each is itself an architecture decision, not a free implementation choice.
3. **λ calibration** — CSG's λ_orth = 0/1/5 were calibrated for full end-to-end CNN training;
   nothing establishes these values (or this parameterization) transfer to a much smaller adapter's
   capacity (`23_Experiment_Contract.md`'s "capacity sanity check," never performed).

## Explicitly prohibited at this stage

No invented design. Not "we use a projection head instead," not "we duplicate the CLS token," not
"we split feature channels" — these are all new architecture proposals, and none may be introduced
unilaterally. **The goal is not to port CSG-Lite to a ViT.** Paper 4 does not need to prove
CSG-Lite's specific design is correct; it needs *a* representation intervention that instantiates
the locked mechanism. A different architecture that preserves the mechanism is fully valid — this is
precisely why the hypothesis was already generalized from "disentanglement → geometry → ..." to
"representation intervention → geometry → accessibility → reliability" (`Scientific_Hypothesis.md`),
specifically to avoid being locked to one implementation.

## Resolution path (two steps, not one)

**Step 1 — Architecture Study (this step, now open, revised 2026-08-05).** Scope: parameter-efficient
intervention / adaptation / debiasing / disentanglement methods on **frozen vision foundation
models** — not OOD detection, not dermatology. Not concerned with any paper's reported results.
Three tiers, in order, each independent of CSG-Lite:

- **Tier 1 — Intervention taxonomy.** Aggregate table, one row per *family* (not per paper):
  `Family | Frozen backbone | Trainable component | Typical placement`. LoRA, bottleneck adapter,
  residual adapter, prompt tuning, feature projector, etc. No commentary — description only.
- **Tier 2 — Mechanism taxonomy.** What is each family actually trying to change? Domain
  adaptation, debiasing, fairness, disentanglement, representation editing, concept erasure, feature
  alignment, etc.
- **Tier 3 — Architectural ingredients.** Strip papers away entirely; count structural ingredients
  across the surveyed set: second/auxiliary encoder, projection head, auxiliary branch,
  orthogonality constraint, adversarial head, feature split. `Ingredient | Frequency`. This is
  where the actual empirical question gets answered: is a dual-encoder structure common or rare
  across existing frozen-FM interventions?
- **Tier 4 — Design Constraint taxonomy** (added 2026-08-05, per Vinh). What invariant is each
  paper trying to preserve — no second encoder, no label supervision, no backbone update, etc.
  List distinct constraints found, with counts. Purpose, stated directly: Paper 4 has its own
  constraint set (frozen PanDerm, no backbone fine-tuning, representation intervention,
  geometry-measurable, Gate 0/Gate 1-compatible) — Step 2's eventual architecture choice should be
  judged on constraint-fit against this taxonomy, not on which existing method looks best in
  isolation.
- **Tier 5 — Geometry-treatment taxonomy** (added 2026-08-05, per Vinh). For each paper: is
  representation geometry explicitly analyzed (linear probes only vs. intrinsic dimensionality vs.
  spectral/eigenvalue analysis vs. not analyzed at all)? Purpose, stated directly: for Paper 4,
  geometry is not a byproduct — it is the hypothesis's mediating variable. Knowing how many
  existing frozen-FM interventions actually measure geometry, versus intervene and stop at
  downstream task performance, is itself a finding — useful for Related Work regardless of what
  Step 2 eventually decides.

**Per-paper table** (the evidence Tiers 1–5 are built from): `Paper | FM | Frozen | Intervention |
Mechanism | Design Constraint | Dual encoder | Orthogonality | Projection | Geometry touched? |
Notes`. **Mechanism** is scientific, not architectural — what the paper is trying to change (e.g.
"suppress protected-attribute information," "shift representation geometry"), distinct from
**Intervention** (architectural — how: LoRA, adapter, etc.) and from **Design Constraint** (what the
paper refuses to change — e.g. "no second encoder," "no label supervision," "no backbone update").
Every cell verified from the actual paper text via search + fetch — nothing invented or guessed from
memory or title alone.

**Stopping rule: theoretical saturation, formalized (2026-08-05, per Vinh) — not a target count and
not "feels saturated."** Stop when **three consecutive papers** add **no new** intervention family
(Tier 1), **no new** mechanism (Tier 2), **no new** design constraint (Tier 4), and **no new**
geometry-treatment category (Tier 5) — all four, not just one. Only then is the taxonomy considered
saturated. Reading further just to hit a number, or stopping early because one dimension stalled
while others are still moving, are both wrong.

**Deliverable:** the per-paper table, the five tier tables, and one summary page — "Architecture
Study Summary" — with counts (intervention families found, mechanisms found, design constraints
found, papers with a dual-encoder/auxiliary-branch structure, papers using orthogonality, papers
that explicitly analyze geometry vs. not). No prose beyond what's needed to present the tables. **No
architecture chosen or recommended for Paper 4 anywhere in this step.**

**Step 2 — Answer AR-01 (not started until Step 1's full deliverable exists and is reviewed).**
Only here does CSG-Lite re-enter — as a reference point to check against the field's map, not as
the starting point — and reasoning become allowed: given Tier 3's ingredient-frequency data and
Tier 4's constraint taxonomy, which ingredient(s) are actually necessary to preserve the mechanism
(representation intervention → geometry → accessibility → reliability) while fitting Paper 4's own
constraint set, independent of whether CSG-Lite happens to use them? This is where AR-01 is actually
decided; Step 1 only produces the map it will be decided from.
